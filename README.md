# sea-orm-typed-id

[![Crates.io](https://img.shields.io/crates/v/sea-orm-typed-id.svg)](https://crates.io/crates/sea-orm-typed-id)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)

A Rust library that provides a macro for generating type-safe database ID types for SeaORM.

## Caveat

You might not actually need this library; it’s just a macro, and you might be better off simply copying the code from src/lib.rs into your project.

## Features

- `all`: Enables all features
- `schema`: Enables `schemars::JsonSchema` support
- `utoipa`: Enables OpenAPI schema generation support

## Installation

Add this to your `Cargo.toml`:

```toml
[dependencies]
sea-orm = { version = "2", default-features = false, features = ["macros", "with-json", "postgres-array"] }
sea-orm-typed-id = "0.6.2"
serde = { version = "1", features = ["derive"] }
```

Version 0.6.2 targets SeaORM 2. Add the SeaORM database driver and runtime
features your application uses. The generated code refers to `sea_orm` and
`serde` directly, so both must be dependencies of your application.

For the optional `schema` or `utoipa` features, also add the corresponding
`schemars` (version 1) or `utoipa` dependency. For example, JSON Schema support:

```toml
sea-orm-typed-id = { version = "0.6.2", features = ["schema"] }
schemars = "1"
```

## Usage

```rust
use sea_orm::entity::prelude::*;
use sea_orm_typed_id::define_id;

// The one-argument form remains backed by i32.
define_id!(CakeId);

// The backing type can also be stated explicitly.
define_id!(FillingId, i64);

#[derive(Clone, Debug, PartialEq, Eq, DeriveEntityModel)]
#[sea_orm(table_name = "cakes")]
pub struct Model {
    #[sea_orm(primary_key)]
    pub id: CakeId,
    pub filling_ids: Vec<FillingId>,
}

#[derive(Copy, Clone, Debug, EnumIter, DeriveRelation)]
pub enum Relation {}

impl ActiveModelBehavior for ActiveModel {}
```

`define_id!` supports `i32` and `i64` backing types. `define_id!(CakeId)` is
equivalent to `define_id!(CakeId, i32)`, while `define_id!(CakeId, i64)` maps to
SeaORM's `BigInteger` column type.

For an auto-incrementing PostgreSQL primary key, SeaORM 2 renders `BigInteger`
as `bigint GENERATED BY DEFAULT AS IDENTITY`. Enable SeaORM's
`postgres-use-serial-pk` feature when the schema should use `BIGSERIAL` instead.

## PostgreSQL arrays

Since version 0.6.1, typed IDs support PostgreSQL arrays, including
`Vec<CakeId>` and `Vec<FillingId>` in entity models. The macro adds
`#[sea_orm(try_getable_array)]`, and the library enables SeaORM's
`postgres-array` feature. The backing type determines whether the database
column is `integer[]` or `bigint[]`.
